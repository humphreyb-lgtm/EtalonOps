# Targeted Azure SQL managed-identity repair

The first West US 3 deployment provisioned the approved infrastructure and schema but the application exited at SQL connection with ELOGIN / “Login failed for user '<token-identified principal>'.” Runtime logs established that the Node application and dependencies loaded; this was not a build or B1 capacity failure.

The migration incorrectly used the system-assigned identity's service principal **object ID** as the SID for `CREATE USER ... WITH SID ..., TYPE=E`. Microsoft's [CREATE USER documentation](https://learn.microsoft.com/en-us/sql/t-sql/statements/create-user-transact-sql?view=azuresqldb-current) explicitly requires the **client/application ID** for service principals and managed identities. The object ID remains correct for Azure RBAC assignments; the SPA application client ID is a third, separate identity and must not be used for the SQL runtime user.

The updated migration looks up the actual pilot app's managed identity, verifies the saved object ID, reads that identity's own application ID, and encodes the client GUID as SQL binary SID. A transaction/application lock protects the repair. If the existing user has the exact known legacy object-ID SID, no unexpected ownership/roles, and the reserved legacy alias is unused, it renames that metadata principal, creates the correct runtime user, restores the same restricted table grants, and revokes object privileges from the legacy alias. No tables or data are dropped. An already correct mapping is unchanged; unknown mappings stop rather than guessing. Runtime Graph permissions, database ownership, passwords and extra roles are not added.

`bash scripts/repair-sql-identity.sh` is intended for the original authenticated Cloud Shell deployment directory. It checks subscription/tenant/identity, opens only an exact temporary Cloud Shell IPv4 rule if needed, runs the idempotent migration/identity repair, removes that rule via cleanup on success or failure, restarts the existing app, and checks SQL health/anonymous API denial. It does not deploy infrastructure, change SKUs, replace the app package or enable AI. If cleanup reports failure, remove only `EtalonOpsIdentityRepair` on the pilot SQL server. Do not rerun the full infrastructure script to perform this repair.

The small repair ZIP contains only the updated migration, its helper and repair runner plus this document. Extract it into the existing `etalonops-westus3` directory; it contains no runtime state, secrets or node_modules. Preserve the existing `.runtime/azure-deployment.json`.

Validation before release: 36 backend tests passed, including distinct client/object IDs, GUID byte order, idempotency and unknown-principal refusal; SQL Server native GUID conversion agrees with the helper. Restricted SQL integration checks and shell syntax checks run locally. The actual external-user DDL and managed-identity login remain live Azure checks; local SQL Server tests do not claim to authenticate a managed identity.
