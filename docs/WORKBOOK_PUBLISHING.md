# Workbook upload and publishing

Administration → Workbook imports accepts a single catalog-template `.xlsx` workbook directly, or a catalog `.csv` file. No CSV splitting or Cloud Shell data-import script is required. The server parses the workbook, retains row/sheet references and saves data in the existing Azure SQL database as unpublished import records. Search, manufacturer choices and MRF creation cannot see those staged records.

Open a saved import, inspect source evidence and generated descriptions, edit and save unpublished fields, or return later. Filter by type, status and text; records are paginated. “Select valid filtered records” selects across all filtered pages. An explicit approval checkbox and Publish selected records action are required. Publishing orders materials before linked products and phrases within one transaction; failure rolls back all selected additions. Unselected records remain unpublished. Duplicate catalog facts are retained, not overwritten; canonical matches reuse existing generic items. The same exact upload reopens its existing queue record instead of duplicating it. When a canonical match has a different key, remaining linked staged rows are adjusted to that canonical key.

Delete selected unpublished records asks for confirmation and removes them from the active review queue, retaining their source records and audit history as deleted. It never deletes previously published catalog records. “Leave unpublished” does not publish or discard saved rows. Published rows cannot be edited or deleted through this staging interface; use existing catalog correction/retirement controls. Staged changes use optimistic versions to prevent overwriting another administrator's work.

Publication and fact verification are separate. AI-origin facts remain provisional at publication and retain provenance. Publication does not independently verify manufacturer claims, allow paid AI, or grant image rights. Image references are held for the separate Product images permission-review process. Incomplete specialty specifications must be resolved or left unpublished, not coerced into standard-conduit identity. Previously published live records are unaffected by uploading revised data and remain searchable until separately retired.

Supported sheets are Conduit, Supports, Boxes, Other Parts, Manufacturer Products, Translations and Image References. Instructions, Research Notes and other worksheets are ignored; their contents are never executed as instructions. Use the provided headers. Dimensions are decimal inches; manufacturer identifiers should be text cells to retain leading zeros. Formulas must be saved as values. `.xls`, macros/external workbook links, formulas, XML entity declarations and oversized archives are rejected. Limits are 3 MB compressed, 20 MB expanded and 2,000 data rows. The parser performs no outbound product/image fetches.

The legacy CSV preview/apply interfaces remain available, with explicitly labeled publication actions. A CSV preview is unpublished; applying/publishing requires the existing review confirmation. The primary Excel workflow is the saved Workbook imports queue.

No new tables or infrastructure are required: queue payloads use new workflow-tagged catalog_batches records, separate from legacy structured batches. Existing runtime permissions suffice. Audit records identify uploads, edits, deletions and publications. The release adds free, open-source workbook parsing packages; no new subscription or paid service is enabled.
