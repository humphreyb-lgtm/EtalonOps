# Workforce and account access v31

This cumulative release adds a contemporary responsive sign-in page with Microsoft and invitation-only site accounts, registration, password-reset requests and single-use reset completion. It replaces basic user administration with dense People / Jobs / Companies screens, contact fields, account status, company authority, multiple job assignments, job roles and per-job reporting relationships. Assigned jobs populate the builder switcher; example job enums are replaced by validated managed IDs throughout the MRF/catalog/research APIs. Catalog data, MRF owners and snapshots are retained. Original Input and Move controls are removed from the MRF Item List.

Migration 12 adds workforce, credential, hashed-token, session and login-throttle tables plus job-role/supervisor membership columns. Applied migration checksums remain unchanged. Restricted runtime grants include the new tables; audit history remains append-only. The updater recovers missing local .runtime/azure-deployment.json settings from existing resources automatically using the existing recovery script; it creates no Azure resources. This release uses the existing App Service/SQL resources and makes no paid AI requests.

Follow [People, jobs and sign-in](SITE_ACCOUNTS_AND_JOBS.md) for administrator steps, password/session behavior, email webhook configuration and remaining approval/MFA work. Site invitations and resets work through administrator-distributed links immediately; automatic email requires the separately configured mail service. Do not share invite/reset links in public channels or commit them.

Extract the source ZIP into the existing Cloud Shell workspace and run scripts/update-cloud-app.sh. Health reports workforce-accounts-v31. Use a private browser or sign out to see the new login screen; an existing valid session correctly resumes the builder. After deployment, verify real Microsoft sign-in, a test invitation, assigned-job switching and company-scoped administration.
