# Material filters, paging and categories v24

Administration → Materials now permits paging, filtering and sorting while retaining unsaved row edits in memory across pages/filters. The v23 pager was disabled whenever any row was dirty, including changing the new row category. Next/Previous now depend only on page boundaries and an active request. Save/discard individual rows as before. Closing Administration or the browser still clears unsaved edits after the existing warning; drafts are not durable saves.

Category selection filters the entire catalog. Add field filter exposes each selected category's fields plus other observed specification fields and Unit. Multiple conditions combine with AND. Equals/Contains apply to text; numeric/measurement fields support equality, At least and At most. Inch values accept fractions. Apply filters runs the search. Sort by description, category, unit, material key or an attribute, ascending/descending. Numeric values sort numerically, with deterministic key/ID ties. Matching counts and pages are computed after filters and sorting, before returning the requested 25 rows. Clear filters resets the query. Fresh clean rows reset on Refresh; dirty rows retain original snapshot hashes for conflict protection.

Manage categories creates custom category names and additional field definitions (text, nonnegative number, positive inch measurement, optional/required). All custom categories retain Type / name and Defining specifications. Custom categories have stable internal IDs and become selectable for entry, filtering and sorting. Names/field labels and required flags can be edited with version protection; existing field keys/types cannot be removed or repurposed. Built-ins remain fixed. There is no automatic recategorization of old materials. Changing an existing material's category uses the existing reviewed replacement process. Add a category, then choose it on a new row to use its fields.

Categories and required-field validation are tenant scoped and admin controlled. Custom category records are included in catalog exports. SQL and SQLite migration 9 adds material_categories; existing migrations are unchanged. The updater applies the migration and grants the existing runtime identity access. No new Azure resource, service, secret or paid AI call is involved.
